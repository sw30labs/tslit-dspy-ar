# TSLIT-DSPy

## What This Is

TSLIT-DSPy (Time-Shift LLM Integrity Testing with DSPy-Powered Analysis) — a framework for detecting dormant adversarial backdoors in open-weight AI models from adversary-nation origins (PRC: Qwen, DeepSeek, MiniMax).

**Author:** Nicolas Cravino (ncravino@mac.com), Cybersecurity Practitioner & AI Security Researcher

**Target audience:** US Government agencies (NSA, IC), Big 4 consultancy firms (Deloitte, PwC, EY, KPMG), critical infrastructure operators.

**Prior submission:** TSLIT v1 (predecessor) was submitted to NSA AISC on January 7, 2026.

## Technical Details

- **Compile model:** Claude Sonnet 4.6 (cloud API)
- **R&D inference model:** Claude Opus 4.6 (cloud API) — best eval signal, no adversary-model contamination in R&D pipeline
- **Deployment validation model:** GPT-OSS-120 BF16 via Ollama (local) — fully open-source, proves local deployment works
- **Auto setting:** `heavy` (matching experiment_config.json)
- **Metric weights:** 0.50 category_accuracy + 0.20 risk_assessment + 0.20 evidence_grounding + 0.10 qa_valid (hardcoded in metrics.py)
- **Autoresearch brain:** GPT-OSS-120B MXFP4+BF16 via Ollama (local) — same model as deployment validation, no adversary contamination
- **Zero-shot baseline (Opus 4.6):** 92.86% accuracy / 83.2% composite on 14-example dev set (13/14 correct, 2026-03-25)
- **MIPROv2 compiled (Sonnet 4.6 compile, Opus 4.6 inference, heavy, 66 trials):**
  - Dev set: **100% accuracy** (14/14), **87.8% composite** — zero-shot false negative recovered
  - Test set: **88.2% accuracy** (15/17), **78.3% composite** — zero false positives, perfect recall on temporal_logic_bomb and combined; 2 false negatives on subtle affiliation_bias (terse compliance gatekeeping)
- **Legacy results (obsolete):** 87.04% composite with Nemotron/Qwen3.5-27B (replaced March 2026)
- **Dataset:** 86 examples (55 train / 14 dev / 17 test) — augmentation to 65 train in progress

## Critical Conceptual Distinction

**Phases A–D are the R&D pipeline** — they build, calibrate, and improve the detection engine. They produce a compiled pipeline artifact (portable JSON with optimized prompts).

**Service delivery is separate** — running that compiled pipeline against client target models (probe campaigns, assessment reports, OSCAL artifacts) is an operational activity described in the whitepaper Section 7. The paper uses "Steps 1/2/3" (not "Phases") for service delivery to avoid confusion.

## Design Decisions

1. **Phase B is a "diagnostic bootstrap", not a permanent operating mode.** Its value is front-loaded for small datasets and gets absorbed into Tier 3 as the system matures. This was a deliberate reframing after analyzing whether Phase B was strictly necessary.

2. **Phase C uses a two-pass compilation strategy.** Fast `--mini` screening (<60s, local) to catch regressions, then batched full recompilation (5-15 min, cloud API) only after 3-5 validated examples. This is a 3-5x API cost reduction vs. naive one-recompile-per-example.

3. **Service delivery uses "Steps" not "Phases"** to avoid confusion with the R&D Phases A-D. Running probes against client models is NOT Phase B or C.

4. **Figures are generated from Python matplotlib**, not hand-drawn. They can be regenerated and modified programmatically.

5. **All 8 bibliography entries were verified via web search.** DSPy is "Declarative Self-improving Python" (Khattab et al., 2023). Karpathy's autoresearch was released March 7, 2026.

6. **No adversary-origin model in the R&D pipeline.** Compile with Sonnet, infer with Opus, validate deployment on GPT-OSS-120 (fully open-source, US-origin). Qwen/DeepSeek/MiniMax are *targets to scan*, never part of the detection infrastructure.
